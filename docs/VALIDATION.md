## 真实链路

已经完成的有界短时测试包括：

- OOPZ 网页 RX 能进入服务器，讯飞能返回稳定转写。
- GPT-SoVITS `api_v2 /tts` 的 raw PCM 能通过 TX 返回指定频道。
- 用户插话后，系统能关闭当前输出并生成新的回复。
- 两路独立虚拟音频设备不会成为系统默认输入或输出。
- 测试音频会话均能在设定时间或显式调用后关闭。

真实测试只覆盖授权房间、有限设备和有限网络条件，不能外推为所有 OOPZ 客户端或所有虚拟声卡组合都可用。

## 声纹与话轮

使用 CAM++ 余弦相似度和 Smart Turn v3.2 的短时对照显示：

| 场景 | 结果 |
|---|---|
| 已注册者正常讲话，3 轮 | 完整交付 0/3；部分窗口通过 2/3 |
| 已注册者短句，3 轮 | 完整输入 1/3；一次只有前段 |
| 已注册者播报中主动打断，3 轮 | 2/3 成功暂停并听到新回复 |
| 未注册者在播报中讲话，3 轮 | 0/3 触发正文、回复或暂停 |

这组结果说明身份门闩和打断路径可以工作，但已注册者仍出现漏识别与短尾过度过滤，不能称为稳定通过。测试中仅本机运行配置使用过 0.40；源码和模板默认仍为 0.65。两个值都需要按实际麦克风、位置、音量和用户样本重新校准。

Smart Turn 已产生真实 `input_complete`，Smart Turn 路径已进入真实房间测试，结论只覆盖这些短会话：

- ASR final 到达后仍需等待语义结束判断。
- 继续说话会使旧结束结果失效。
- 语义结束长期不确定时返回 `input_uncertain`，不伪造完成事件。
- 自然句中停顿、真正结束、短附和和未说完后续说的系统化专项验收尚未完成。

## Instant 与提前播报

合成文本基准使用本地 Qwen3.5 9B、8192 上下文、并行 1。三轮最终代码对照的中位数：

| 阶段 | 中位耗时 |
|---|---:|
| 请求 → 首段非空内容 | 0.1419 s |
| 请求 → 完整 speech 可交 TTS | 0.3908 s |
| 请求 → 完整 JSON 校验 | 1.4547 s |

完整 JSON 相对非流式完整返回没有明显加速；收益主要是 speech 比完整 JSON 提前约 1.0 秒可用。27B Instant 在严格服务端 JSON Schema 下出现超时，因此没有作为当前快速路径。

关闭声纹后的真实 OOPZ 9B 短时测试收集了 6 个成功回复样本，服务端中位阶段为：

| 阶段 | 中位耗时 |
|---|---:|
| RX 语音结束 → ASR final | 0.859 s |
| ASR final → 模型请求 | 0.055 s |
| 模型请求 → 首段内容 | 0.440 s |
| 模型请求 → speech 校验完成 | 0.717 s |
| 模型请求 → 完整 JSON | 1.542 s |
| TTS 请求 → 首块 PCM | 0.915 s |
| RX 语音结束 → 本地 TX 提交 | 2.521 s |

6 次均先完成 speech 再做完整 JSON 校验；其中 1 次首块 TX 在完整 JSON 之前提交。用户确认插话能停止旧播报并收到新回复，但小模型的回复质量仍可能偏离上下文。

这些时间来自本机单进程时间戳，不包含跨设备时钟同步，也不等于用户远端听到声音的完整时延。

## 网页自动入房

目标域能通过网页界面打开，但语音频道自动加入仍未成功。已测试的默认双击、右键菜单和可访问性激活都没有同时满足“目标成员出现在语音频道”和“页面显示已连接”的证据。当前方案保留为 [自动入房研究](OOPZ_AUTO_JOIN_RESEARCH_2026-10-27.md)，不进入生产工具。

## 后续验收

1. 修正已注册者在自然停顿和短尾场景中的漏识别，但不能把旁人音频拼入候选上下文。
2. 完成 Smart Turn 的句中停顿、续说、正式结束和意义短句专项测试。
3. 用更多注册与未注册声音校准阈值、margin、窗口和最小有效语音。
4. 研究重叠说话的真实分离；CAM++ 只做身份判断，不是语音分离。
5. 在功能与身份可靠性稳定后，再单独处理延迟、唤醒词或跨平台部署。
