已按用户选择改为：完整 speech 字段通过校验后立即安排 TTS，完整 task JSON 通过校验后再交给 Agent。首段内容、speech 可交付和 JSON 完成分别计时。本轮真实推理仅使用合成文字“把菜园里的菜都收一下”；没有打开 OOPZ 音频、调用真实 Juno 或执行 MC。

## 9B：最终代码的三轮流式／非流式对照

当前使用 `lmstudio/qwen/qwen3.5-9b`，GGUF Q4_K_M。每轮先 stream，随后非流式；始终单请求、单模型、8192 上下文、并行 1。模型已加载；第 1 个流式请求是本次重新加载后的首请求，但不是证明过的磁盘／硬件冷启动。第 2、3 轮为热请求，可能受提示缓存影响。非流式基线读取 Git e60d027 的原 adapter；脚本断言 SYSTEM_CONSTRAINTS 和 schema 完全一致，场景、temperature=0.1、max_tokens=512 和 reasoning_effort=none 相同。

单位：秒，从各自 generate 调用开始。流式的阶段由生产 adapter 回调计时；非流式为调用到完整解析返回。表中不是首音频、远端听音或完整语音链路延迟。

| 次数 | 首段非空内容 | 完整 speech 可交 TTS | 完整 JSON 校验完成 | 非流式完整返回 |
|---|---:|---:|---:|---:|
| 第 1 轮 | 0.5001 | 0.7527 | 1.7873 | 1.4186 |
| 第 2 轮 | 0.1419 | 0.3908 | 1.4547 | 1.4093 |
| 第 3 轮 | 0.1412 | 0.3825 | 1.4326 | 1.4952 |

三轮流式与三轮非流式均通过严格 JSON、非空语音及“全部收获”范围核对。流式首段中位 0.1419 秒，speech 中位 0.3908 秒，完整 JSON 中位 1.4547 秒；非流式完整返回中位 1.4186 秒。完整生成没有表现出提速，收益在于同次流式请求的 speech 比完整 JSON 提前约 1.03–1.06 秒。这是可启动 TTS 的时间差，不是已经实测的远端听感改善。

场景、请求长度和机器状态只覆盖这组小样本；顺序不是随机交叉，不能将细小总耗时差异推断为普遍吞吐优劣。返回的确认语为“好的，我准备帮您收获菜园里所有的作物。”，任务有 all=true；未声称已收获。

9B 三轮对照使用同一套严格 schema 与提前 speech 边界。此前还做过三轮预飞对照，但之后收紧了 stop chunk 已知无效结果不能首次播报的边界，因此两组没有合并。原始 JSON 包含本机运行状态，不随公开仓库分发。

## 27B 无审查 Instant：生产路径失败，隔离诊断可生成

本次使用准确预设 `lmstudio/local/qwen3.8-27b-512k-instant`，其基础权重为 `orcarouter/Qwen3.8-27B-Uncensored-MLX-512K-Text`，MLX 4bit。使用预设自身的默认关闭思考字段，并发送 reasoning_effort=none；仅把此次加载限制为 8192/parallel 1，没有修改持久预设。每次切换都先卸载并确认空载。请求期间每约 2 秒核对唯一实例、8K 和无排队；任何失败后不继续发请求，先关闭 HTTP 再卸载。

带生产严格 response_format=json_schema 的流式请求 **1 次尝试、0 次成功，30.0023 秒超时**；没有首段内容、speech 或完整 JSON。请求期间上下文保持 8K，状态停在 processingPrompt，无排队。随后停止未执行的第 2、3 轮并卸载。它不适合直接作为当前 8 秒超时的快速路径。

为隔离原因，重新加载同一模型，仅在测试传输层移除服务端 response_format；场景和生成参数不变，生产本地严格 schema 校验仍然执行。该诊断没有改动运行配置，也不是已启用的生产替代方案。一次首请求加两次重复的结果如下：

| 次数 | 首段非空内容 | 完整 speech | 完整 JSON | 本地严格校验 |
|---|---:|---:|---:|---|
| 第 1 次 | 1.3620 | 2.0722 | 5.2360 | 通过 |
| 第 2 次 | 1.0560 | 1.7379 | 4.7915 | 通过 |
| 第 3 次 | 0.9993 | 1.6716 | 4.8120 | 通过 |

诊断三次均有非空确认语、完整任务和“全部”的范围，未观察到 reasoning 文本事件。中位分别为 1.0560 / 1.7379 / 4.8120 秒。三次无约束返回恰好通过本地校验，不能证明去掉服务端约束后始终格式可靠。原始运行 JSON 不随公开仓库分发。

证据支持“故障与服务端结构化约束路径有关”的判断；尚未定位到具体运行时代码，不能声称已证明是 grammar 编译或模型解码速度的问题。LM Studio 官方说明 GGUF 和 MLX 的结构化输出分别使用 llama.cpp 与 Outlines，底层路径不同，见[官方文档](https://lmstudio.ai/docs/developer/openai-compat/structured-output)。诊断路径与9B生产路径约束不同，不能作为完全同条件模型排名。

此前alias从8K变成512K的日志复核：原8K实例在最初请求期间仍存在；后续先报 Model unloaded，再出现另一请求和新实例。这更符合实例卸载后新请求触发JIT、使用持久512K默认值。谁触发了旧实例卸载尚不确定，不能归因首次Magpie请求覆盖了8K。本轮未出现该重载；没有修改全局JIT设置或任何模型文件。

## 行为与回归

新增的是有界 SSE 解析、可选提前语音回调，以及会话对提前播报的版本核对与失败处理。生产正文上限64KiB、SSE协议总量256KiB、总超时继续生效。仅完整且合法的首个speech字符串可提前交付；如果task先来则等待全文。stop即检查已结束全文，DONE后才交付任务；非法尾部立即停止同epoch的提前播报。新输入、停止、换人、输入不确定、Agent替换、TTS失败和迟到数据不能恢复旧播报或交付旧任务。

完整离线回归 **132/132 通过，15.935 秒**，比前版新增 16 项测试。Ruff、format、Pyright 通过。覆盖 UTF-8/CRLF 与分块、半字符串/转义/任务先输出、错误事件、重复键、截断、大小和超时边界、提前播报后坏尾、Agent 替换、取消各阶段及 TTS 失败。发布前完整测试又扩展到 134 项并通过，见[验证摘要](VALIDATION.md)。

当前配置保持Magpie的9B路由，运行配置哈希不变；最后只保留9B、8192、parallel1、idle、queued0。声纹阈值仍0.40，模型、注册模板和分段没有变化。完整 JSON 失败前已经播出的确认语无法撤回；错误事件带quick_reply提醒Agent不要重复确认，任务仍未执行。

未进行真实STT到模型计时、Juno首音频、OOPZ听感/打断或MC执行验收；未修复既有声纹与短尾问题；未做60分钟测试。
